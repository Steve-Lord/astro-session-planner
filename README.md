# Astro Session Planner

A deep-sky astrophotography night planner: pick a site, see what is worth shooting tonight, and plan the session around your horizon and the Moon. A static web app (Svelte 5 + TypeScript + Vite) with no backend, installable as a PWA (on iPhone: Safari, Share, Add to Home Screen) and usable offline after one load.

## Privacy

Your site location and horizon profile are stored only in your browser (local storage) and never leave your device. The only thing that would ever be sent anywhere is a weather lookup (a later feature), and that would send coordinates rounded to a coarse precision, nothing else.

## Gear

Set Mount to Equatorial when the Seestar is polar-aligned on a wedge; targets passing overhead then count all the way up. Alt-az (the default) stops at 80°, where alt-az tracking fails.

## Horizon sweep (phone)

Sweep your skyline with the phone instead of drawing it by hand. This needs a phone or tablet with motion sensors and a camera: iPhone Safari is the primary target (Safari tab or Home Screen app), Android Chrome is best-effort. Laptops and desktops have no motion sensors, so there the sweep is unavailable and you use the manual editor, or sweep on your phone and send the result across.

1. **Sweep.** On the Sites screen, tap Sweep horizon on the site. Stand where the telescope goes, hold the phone upright in portrait with the rear camera facing the horizon, and keep the on-screen line on the top edge of roofs and trees. Turn slowly all the way round, then tap Done. Samples are rejected while the phone is tilted or rolled, moving too fast, the compass is disturbed (for example by nearby metal), or the compass accuracy is poor (worse than 25 degrees); the screen tells you why. The ring on the sweep screen lights up the directions you have covered; uncovered directions stay unlit. Gaps of 5 degrees or less are interpolated. When you tap Done, larger gaps are listed ("Not swept: a°–b°"): sweep them, or choose Fill from neighbours. Filled directions are shown hatched in the editor. Switching away from the app, a call, or the camera being taken by another app pauses the sweep, and so does the Pause button; tap Resume to carry on. If the screen keeps saying the compass is disturbed, move away from metal, then tap Pause and Resume so the compass reference is learned again.
2. **If motion access was refused (iPhone).** Close Safari (or the Home Screen app) completely, reopen it, tap Start, and choose Allow.
3. **Save.** After Done, the sweep opens in the horizon editor as unsaved changes. Tap Save now (or Save horizon) straight away: an unsaved sweep exists only in memory, and iPhone Safari can discard a page in the background. You can calibrate later.
4. **Calibrate north (recommended, usually after dark).** Open Edit horizon and tap Calibrate north. Compasses drift near buildings (10–20 degrees is realistic), so aim at something whose true position the app knows and lock on. Calibration is offered for horizons swept on this device, including ones you have touched up since; imported and hand-drawn horizons cannot be calibrated. Swept horizons that are not calibrated yet show an "Uncalibrated" badge. Targets must be between 5 and 60 degrees up and at least 30 degrees from the Sun: the Moon at any time; Venus once the Sun is below the horizon; Jupiter, Saturn, Mars and bright stars only once the Sun is 6 degrees below the horizon. The Sun is never offered. Calibrating again replaces the previous correction; it does not stack. Save again after calibrating.
5. **Touch up.** The editor lets you adjust the shape. Dragging points or Reset flat marks the horizon as manual when you save it (marking trees does not). A touched-up sweep can still be calibrated; Reset flat removes everything the sweep measured, including the calibration option.
6. **Send to laptop.** Save first, then in the horizon editor tap Send to another device. You get a QR code and a Copy link button, plus a Share… button where the device supports sharing (AirDrop, Messages). The link carries only the horizon shape, no location or site name. On the other device, opening it asks which site it belongs to (an existing site or a new one) and asks before replacing an existing horizon. A link opened on the iPhone itself opens in Safari, whose storage is separate from the Home Screen app.

## Development

```sh
npm ci
npx playwright install chromium   # one-time, for the e2e tests
npm run dev        # dev server
npm test           # unit tests (Vitest, tests/unit)
npm run check      # svelte-check + tsc
npm run build      # production build into dist/
npm run e2e        # builds, then Playwright smoke tests against vite preview
```

Icons are generated by `node scripts/make-icons.mjs` (Node built-ins only) and the PNGs are committed.

## Catalog

`public/catalog.json` is built from OpenNGC data with `npm run build:catalog` (`scripts/build-catalog.ts`). Rerun it to rebuild the catalog.

## Deployment

Pushing to `main` runs `.github/workflows/deploy.yml`: unit tests, type checks, e2e, then deploy to GitHub Pages.
