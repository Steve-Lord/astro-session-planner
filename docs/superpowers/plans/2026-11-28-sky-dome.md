# Sky Dome Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Sky tab: a round, top-down map of the sky with the owner's roofline, tonight's top 30 targets, the Moon and bright stars, a sunset-to-sunrise time slider, and tap-through to the existing detail screen.

**Architecture:**
- The date, catalogue and plan move out of `Tonight.svelte` into a shared store, so Tonight and Sky read the same night. The site/gear/filter/date controls become one shared component.
- A pure module `src/lib/sky/dome.ts` precomputes per-step positions for the night on the planner's 5-minute grid, using the same position and horizon functions, and provides the polar projection.
- `SkyView.svelte` (the tab) and `SkyDome.svelte` (the SVG) draw it. The detail screen is reused, with a "from Sky" address.

**Tech Stack:** Svelte 5 runes, TypeScript strict, Vite PWA, Vitest, Playwright, astronomy-engine.

**Spec:** docs/superpowers/specs/2026-11-24-sky-dome-design.md (approved 2026-11-28). It amends §7.7 and §7.3 step 5 of docs/superpowers/specs/2026-11-22-astro-session-planner-design.md.

## Global Constraints

- The dome must never disagree with Tonight. It uses the same plan, date, site, gear and filter, and the same positions (`altAz`, `precessToDate`, `heightAt`, `neededHeight`, `moonAltAz`, `moonIllumination`, and the `nightSeries` grid).
- Targets: the **top 30** of `plan.entries`, in plan order, whatever Tonight's "Show more" shows. **Labels on the top 10**; the rest are dots whose name shows on tap.
- Faint at a step means not usable by the planner's sample rule: `alt < gear.minAltDeg || alt > gear.maxAltDeg || alt < needed`. A target below 0° is not drawn.
- Projection: radius ∝ `90° − alt`, north up, **east left**.
  - Faint rings at 30° and 60°.
  - A dashed ring at `gear.minAltDeg`.
  - A dashed ring at `gear.maxAltDeg` only when `maxAltDeg < 90`.
- Obstructions are filled from the edge to `heightAt(profile, az, treesBare)`. Seasonal degrees get a different shade. With no horizon saved: no fill, and the note `No horizon saved for this site`.
- Moon: a disc with its illumination %, drawn only while its altitude is > 0.
- Bright stars from `BRIGHT_STARS` (precessed): drawn only when the Sun is below −6°, dimmer than the targets.
- Slider:
  - It runs from sunset to sunrise on the `nightSeries` grid, with hour ticks in the site time zone and twilight shaded along the track.
  - It starts at "now" when now is within the night span, otherwise at the dark-window start (the span start when there is no dark window).
  - It follows the clock only while the date follows the clock, the slider is untouched and the page is visible. "Touched" resets when the night changes.
  - Before dark it shows a line `Dark in Hh MMm`.
- Address: `#target=<id>&date=…` with no `from` keeps opening in Tonight, unchanged. A detail opened from Sky adds `&from=sky`, opens in the Sky tab, and its back link reads `‹ Sky`.
- The Sky tab stays mounted while hidden, as Tonight and Sites do.
- Phone first: 390 px with no horizontal scroll, tap targets ≥ 32 px. Use the dark-theme tokens from `src/app.css`. The map is SVG scaled to the card width.
- No new network calls. Pushing redeploys the live site: the controller asks the owner before any push.

## Review Focus

1. A site with no horizon saved: the dome draws with no fill and shows the note. Pinned in Task 3 (e2e).
2. A night with no dark window (Oslo, midsummer): the frames still build, the slider works and no stars are drawn. Pinned in Task 2 (unit) and Task 3 (e2e: no crash, empty-state text).

### Task 2: Dome geometry and per-step positions

**Files:**
- Create: `src/lib/sky/dome.ts`
- Test: `tests/unit/dome.test.ts`

**Interfaces:**
- Consumes: `nightSeries` (for its grid and twilight), `altAz`, `lstDeg`, `precessToDate`, `moonAltAz`, `moonIllumination`, `sunAltAz`, `heightAt`, `neededHeight`, `fovArcmin`, `BRIGHT_STARS`.
- Produces:
  - `export function project(alt: number, az: number, radius: number): { x: number; y: number }`. Centre at origin, `r = radius·(90 − alt)/90`, `x = −r·sin(az)`, `y = −r·cos(az)` (north up, east left).
  - `export function obstructionPaths(profile: HorizonProfile | null, treesBare: boolean, radius: number): { roof: string; trees: string }`. These are SVG path strings; both are `''` for a null profile. `trees` covers seasonal degrees only; `roof` covers the rest.
  - `export interface DomeTrack { id: string; alt: Float32Array; az: Float32Array; usable: Uint8Array }`
  - `export interface DomeFrames { times: number[]; span: TimeWindow; dark: TimeWindow | null; twilight: NightSeries['twilight']; sunAlt: Float32Array; moonAlt: Float32Array; moonAz: Float32Array; moonIllum: Float32Array; targets: DomeTrack[]; stars: { name: string; alt: Float32Array; az: Float32Array }[] }`
  - `export function domeFrames(site: Site, gear: Gear, settings: Settings, date: string, targets: Target[]): DomeFrames`. The grid, span, dark and twilight come from one `nightSeries` call (use the first target, or a dummy target at RA 0, Dec 90 when the list is empty). Per-target alt/az use the same precession epoch (dark midpoint) and the same formulas as `nightSeries`. `usable` follows the Global Constraints rule.
  - `export function initialIndex(times: number[], now: number, dark: TimeWindow | null): number`. Inside the span it returns the nearest step to `now`; otherwise the first step ≥ `dark.start`, or 0 without a dark window.

- [ ] **Step 1: Write failing tests** in `tests/unit/dome.test.ts` (London site and Seestar fixtures as in `series.test.ts`):
  - `project(90, 0, 100)` ≈ `{0,0}`; `project(0, 0, 100)` ≈ `{0,-100}`; `project(0, 90, 100)` ≈ `{-100,0}` (east left); `project(45, 180, 100)` ≈ `{0,50}`.
  - For M31 on 2026-11-22: `domeFrames(...).times` deep-equals `nightSeries(...).times`, and `targets[0].alt` equals the series `alt` element by element (exact, both Float32).
  - `usable[i] === 1` exactly when `alt ≥ minAltDeg && alt ≤ maxAltDeg && alt ≥ needed[i]` from the series, for every i.
  - On Oslo (lat 60) 2026-06-21 with an empty target list, `domeFrames` returns `dark === null`, `times.length > 0`, and every `sunAlt[i] > -12`.
  - `obstructionPaths(null, false, 100)` → `{ roof: '', trees: '' }`. A profile with seasonal degrees 90–120 gives a non-empty `trees`; with `seasonal` all false, `trees === ''`.
  - `initialIndex`: `now` inside the span returns the nearest index. `now` a day earlier returns the first index at or after `dark.start`. With `dark === null` and `now` outside the span, it returns 0.

  - Each target is a `<g class="target" data-id={id}>` with a dot, plus a `<text>` label for the top 10. The class `faint` is applied when it is not usable at the step.
  - The Moon is a `<g class="moon">` with its `%` text.
  - Stars use `<g class="star">`.
  - Compass labels: `N`, `E`, `S`, `W`.
  - A dot's tap area is a transparent circle with a radius of at least 16 px in screen terms.

  - Renders `<h2 class="page">Sky</h2>`, then `<NightControls />`, then the dome, then the slider.

  - The `Dark in …` line shows when the step is before `dark.start`.
  - Shows `No targets are usable this night.` when the plan has no entries.
  - Shows `No horizon saved for this site` when `site.horizon === null`.
  - Frames are recomputed (`$derived`) from `night.plan` (top 30 entries' targets), site, gear, settings and date.
  - Clock following: a 60 s interval, active only while the page is visible, `!night.picked`, and the slider untouched. "Touched" is cleared when `night.date`, site or gear changes.
